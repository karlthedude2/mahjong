# Face Sets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Players choose a face set for Mahjong 3D and the Cube from a Stone and Face card. Today's art becomes the "Standard" set in `faces/standard/`.

**Architecture:** A `FaceSets` catalog in the client, like `TileSets` and `Backgrounds`, owns the folder layout and the picture URLs. `FaceArt.Pictures` takes the chosen set. `PlayerPreferences` keeps the choice in the browser. `SettingsChoice` carries it, and `Play.razor` passes it to `Board3D` and `CubeBoard`, which redraw when it changes.

**Tech Stack:** Blazor WebAssembly (.NET 10), xUnit, Python (ship-faces tool).

**Spec:** `docs/superpowers/specs/2026-10-22-face-sets-design.md`

## Global Constraints

- Face set folders: `wwwroot/faces/<id>/<face>.webp` and `wwwroot/faces/<id>/dark/<face>.webp`. The first set has id `standard` and name "Standard".
- Light or dark stays the server's `Cube:StoneFaces`. No player control.
- New text goes through `L[...]`, with Spanish entries: "Face" = "Cara", "Standard" = "Estándar".
- Stage files by name only (the user's tile/logo experiments stay unstaged).

## Review Focus

1. A saved face set id that no longer exists falls back to Standard (Task 1 test).
2. Every shipped set has a light and a dark picture for every face (Task 1 test, per set).
3. Changing the face set mid-game redraws the board with the new art, and doesn't keep the old pictures (Task 2: `@key` includes the set; checked in Task 4).
4. On the Stone and Face card, a dark stone (Onyx) shows the dark pictures (Task 3 test).
5. The 3:2 row at 375px in Spanish: "Piedra / Cara" and the Background name fit or end in "…" (Task 4).
